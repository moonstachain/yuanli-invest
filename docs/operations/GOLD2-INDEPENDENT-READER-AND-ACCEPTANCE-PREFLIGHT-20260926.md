## 独立 reader 实现边界

新模块 `gold_au_independent_reader.py` 与 `gold_au_reader_journal.py` 独立于既有七个冻结生产模块。构造必须读取已配置的 broker_reader 私有身份，不创建密钥或交易授权。真实 PID、reader 密钥指纹、源码身份以及与 runtime 的隔离，必须由独立控制面证明；注入 callback 本身不是隔离证据。

原生订单依靠不可变 command/claim/platform/CTP 映射绑定，禁止按价格、数量、时间猜委托。母子单配对核对使用四个实际生产者在同一证据截面产生的回执。四个不同名称或四个返回 True 的验签函数不足以证明独立：验签结果须提供实际固定验证密钥指纹、签署身份和被验证原文哈希，四方验证密钥必须不同。reader 不持有四方生产者私钥，也不从 broker 数字复制其它三方数据。

发布在外部写入前登记 exact evidence ID、事实哈希、种类与原观察时点。回执未知或写入异常后不得换 ID 重发；重启只能按原 ID 向远端读回。读回确认不刷新历史观察时点、不解除未知写入冻结、不释放订单 claim。私有本地 journal 只是持久恢复线索，不能充当远端不可变证据或独立真值。缺失、损坏、身份变化及权限不符合要求均须拒绝恢复。

旧 PRE_CLAIM/TERMINAL 接线、真实成本政策、跨交易日档案与四方日结仍各有验收要求。该新模块未上传或启动，不纳入既有生产源码审核 pin；正式新开仓门 `LINKED_PROTECTIVE_EXIT_REAL_ACCEPTANCE_REQUIRED` 保持。

## 已明确的工程入口缺口

`gold_paper.py` 已支持 `ENGINEERING_TEST` 与唯一 `engineering_test_command_id` 校验，但生产 runtime 在判断 reason 前拒绝一切 OPEN，现有 main 只接受生产 factory 类型。R2 仅是未授权合同生成器，没有独立工程运行入口。因此不能依靠清 flag、直接注入低层 runtime 或等待真实工程成交来自动解除这个循环。

后续须增加独立、一次性的 engineering factory / entrypoint，仅接收已授予的那一个工程 command 和 R2 固定限制；真实身份、成本、账户互斥、读账、保护退出与独立签名来源仍前置。它保留正式 production OPEN 门，以工程账记录，不计投资样本，不启动运营观察。既有受控工程授权不需重复索取；缺口是代码入口与实际事实，不是授权尚未给出。具体审核规格见私有 `reader-deployment-gap-check.md`，本轮尚未实现该入口。

现有正式退出提前量为 15 分钟，若工程期限为入场后 120 秒，会在确认持仓后立即触发减仓；这满足“最多 120 秒、尽早退出”，不能声称必然持有 120 秒。工程合同还须把“保护平仓的前置证据”与“平仓后的四方结算/跨日日结档案”分清，后者不能被误设为第一次保护平仓的前置条件。正式 5/20 交易日规则保持。
