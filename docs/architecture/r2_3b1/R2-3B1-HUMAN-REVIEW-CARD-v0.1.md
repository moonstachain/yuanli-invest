# R2.3-B1｜P0 Capability Contract Specification｜Human Review Card v0.1

This gate reviews **specification quality**, not implementation quality, trading merit or benchmark performance.

## D1｜B0 contract inheritance
PASS if CAP-R-01 / CAP-V-01 / CAP-XS-01 each instantiate all 11 accepted B0 contract blocks without changing the stable question identity.

## D2｜CAP-R-01 semantic integrity
PASS if R remains a typed decomposition of `P.capital`, not a fourth human world, and the seven minimum state dimensions remain distinct.

## D3｜CAP-R-01 causal humility
PASS if causal claims require explicit identification and descriptive latent states, correlation, feature importance or Granger precedence cannot self-promote to causal authority.

## D4｜CAP-V-01 inverse-pricing integrity
PASS if V extracts price-implied assumptions/regions rather than emitting target price, canonical upside %, or one universal valuation formula.

## D5｜CAP-V-01 identification honesty
PASS if under-identification, risk-premium/expectation confounding, sensitivity and model disagreement are explicit typed outputs/degrade states.

## D6｜CAP-XS-01 cross-asset integrity
PASS if `Structural Asymmetry Source` remains the mother concept and asset-specific implementations are routed without turning Value Control Point into universal ontology.

## D7｜X boundary integrity
PASS if Xs does not silently absorb Xa activation, Xp payoff geometry, V price gate or S survival gate; `X := (Xs, Xa, Xp)` remains intact.

## D8｜Evidence + PIT integrity
PASS if all three specs require `as_of`, evidence cutoff, PIT availability, publication lag/revision semantics, falsifiers and fail-closed behavior.

## D9｜Benchmark + scientific qualification
PASS if simpler baselines, PIT/OOS, regime holdout, false alarms, calibration where applicable, multiple-testing control, complexity penalty and failure receipts remain mandatory.

## D10｜Settlement quality
PASS if each capability defines future settlement observables that test the research state/mechanism rather than simply testing whether an asset price went up.

## D11｜Runtime reproducibility
PASS if `InvocationEnvelope` + `ResearchReceipt` remain mandatory and provider runtime does not become capability identity.

## D12｜Governance boundary
PASS if B1 does not authorize algorithm/provider implementation, Capability promotion, Evidence/Outcome admission, A9 switch, portfolio weights, target prices, buy/sell or live execution.

## Human Gate

If D1–D12 pass, owner may accept with:

`ACCEPT_R2_3B1_P0_CAPABILITY_CONTRACT_SPECIFICATION`

Acceptance does not imply merge or implementation. Separate authorization remains required for each later stage.
