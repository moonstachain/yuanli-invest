# GOLD2 independent paper engineering candidate V4

This candidate adds a separate engineering factory and entry point. The production factory and `ENTRY` admission remain in force. Source approval, compilation, local PostgreSQL checks and an inert bundle are not broker admission or evidence of a SimNow trade.

## Frozen case

`build_engineering_runtime` accepts one exact signed `ENGINEERING_TEST` / `OPEN_LONG` command, one AU contract, one account and one one-shot grant. It accepts no production `ENTRY` command. R2 limits are one lot, stop distance at most 4 yuan/gram, planned loss at most the smaller of 5,000 yuan and the existing budget, five ticks each side plus actual fees, margin at most 30%, at most 120 seconds, early exit and no overnight holding. Fresh native quotes are checked before claim and submission; a drift from the prepared reference blocks submission.

`engineering_main` is distinct from the default production `main`. The generated source has no runtime instance, account credential, grant or signing private key. A live host needs native Python >=3.12 and the `paper-control` dependency (`cryptography==50.0.1`). A Python 3.9 parent invoking a 3.12 subprocess does not meet that host requirement.

## Independent control

The additive migration `20260927072225` is inert: it provisions no runtime binding, deployment, active engineering policy or admission. Operators must provision exact deployment and case policies through an independently scoped administration path.

`admit_reader_bootstrap` atomically consumes a stable account's first-bootstrap qualification, binding deployment ID, source, journal, PID, nonce and isolation evidence. Restarting or changing those values does not mint a new qualification. Exact retries return the original receipt and time. Read operations supply historical facts and never become new admission.

`prepare_engineering_case` verifies the frozen contract, native flat position and zero in-flight orders, actual cost and margin, strategy allocation, approved session, account and robot. Edge performs an independent read after each write and validates identity, source, status and exact immutable receipt fields before signing it.

The server holds a dedicated Ed25519 signing key. The client pins only its public key and validates raw material hashes, fingerprint and signature. Role-scoped HMAC request authentication remains separate. Missing control signing configuration disables these new admission operations; it does not grant broker permissions.

## Recovery and acceptance

An uncertain write or order freezes new submissions. Read-back never automatically resets the freeze. A submitted close is consumed even when rejected or uncertain; automatic duplicate sells are forbidden. Late restarts cannot reuse a preparation older than 15 seconds. Existing linked position recovery applies, and an unresolved account requires supervised recovery recorded as a separate event.

An independent review covers Python, real PostgreSQL 17, Edge HMAC requests, server Ed25519 signatures and the actual pinned Python verifier. Production acceptance still requires native host verification, independent fact producers, real SimNow read-back, one controlled open/close, native zero position and zero orders, four-way reconciliation and daily settlement. Engineering trades never count as investment observations and never start the formal 30-day clock.

The old default `main` remains the production entry. Roll back routing and source to the prior deployment; preserve immutable case, bootstrap and order records. Do not delete an admission to make a retry appear new.
