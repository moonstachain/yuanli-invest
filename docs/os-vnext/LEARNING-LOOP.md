# Reality Learning Loop vNext

## The loop

`Theory → Hypothesis → Capability → Runtime → Replay → Benchmark → Failure → Future Settlement → Capability Revision`

The loop is the mechanism by which research intelligence compounds.

## First-class learning objects

### FutureSettlement

Records what was knowable at the original `as_of`, what later occurred, the settlement window and what claims were supported, contradicted or remained unresolved.

### FailureRegime

Describes conditions under which a capability fails, becomes unstable, loses calibration or ceases to add value beyond a simpler baseline.

### CapabilityRevision

Links prior capability version, triggering evidence/settlement, semantic or algorithmic delta, expected improvement and required re-benchmarking.

## Promotion law

A capability cannot be promoted merely because an implementation exists.

The intended maturity ladder remains:

`concept → specified → implemented → replicated → benchmark_passed → shadow_qualified → canon → deprecated`

Each transition must be receipt-backed.

## Receipt = Ledger; Status = Projection

Factual events should be represented by immutable receipts or externally verifiable GitHub/runtime facts.

`CANON-STATUS.json` is a deterministic projection and must never be treated as the source of historical truth.

This avoids self-reference: a file in a PR cannot know its future merge commit before the merge occurs.
