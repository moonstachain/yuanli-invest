# Semantic Authority Precedence vNext

When historical documents conflict, semantic authority follows this order:

1. **OS vNext Constitution and contracts**
2. **R2 Constitutional Decisions**
3. **R0 Research Capability Canon Reframe**
4. **M1 PNX-S Theory Canon**
5. **Q0 Bootstrap Architecture**
6. Earlier bootstrap / reconstruction material

Historical artifacts remain immutable evidence of project evolution. They are not deleted merely because a higher semantic authority supersedes them.

## Supersession law

A newer authority may:
- supersede semantics;
- preserve historical IDs;
- create successor objects;
- deprecate old projections.

It must not silently rewrite historical meaning.

## Specific precedence decisions

- `ResearchCapability` remains the durable center object.
- `ResearchStateVector` becomes the canonical machine state for a research target.
- `ForceClassification` becomes a human/research-priority projection.
- `X := (Xs, Xa, Xp)` overrides legacy undifferentiated Convexity semantics.
- Portfolio `S` overrides legacy issuer-level use of the term Survival.
- transport-neutral invocation contracts take precedence over legacy REST endpoint lists as Canon semantics.
- receipts and external merge facts are factual ledger inputs; status files are projections.

## Legacy lanes

- M1.2 historical semantic value is preserved, but remaining successor work is Runtime State Contract.
- Q1 historical provider work is preserved, but successor work is Wind Provider Qualification.
- A6 is an Audit / Historical Replay lane, not a universal real-time runtime gate.
